# ogs-ts-unreal working conventions

- The serializer in Source/OgsTelemetryCore writes the standard's
  canonical OGS encoding and must byte-match
  ../OGS-Telemetry-Standard/conformance (run Test/ogs_conformance after
  any change). OgsTelemetrySchema.h is generated by
  ../ogs-ts-dotnet/capnp/gen_writers.py --lang cpp — never hand-edit it;
  regenerate after a schema change (README has the command).
- No third-party dependencies ever: UE games and the ue4ss/uevr mods that
  vendor these headers ship nothing extra. std-only C++17 headers in Core
  (uevr-ogs-ts builds them as C++17).
- Frame conversion (UE LH X-fwd Z-up -> standard LH Z-fwd Y-up) lives in
  OgsTelemetryFrame.h and must stay covered by the conformance binary's
  conversion checks.
- The unit-conversion table in TelemetryPublisherComponent must stay in
  lockstep with ogs-ts-dotnet's Conversions (same pairs, same factors).
  Verified in-engine by OgsConversionTestActor paired with
  TelemetryReceive (expected wire values in the actor .cpp).
- UE test projects consume a *copy* under <project>/Plugins/OgsTelemetry —
  after changing the plugin run ./sync-plugin.ps1 -Project <path> (add
  -Build to compile the Editor target) so the copy never drifts.
- TestProject/ is the in-repo host project: ./sync-plugin.ps1 -Project
  ./TestProject -Build compiles the UE module from the repo alone (no
  external project). Target rules must use V7 + Unreal5_8 to match the
  engine's own build (common-build-products rule rejects diverging
  warning levels).
- Products docs describe current state only; history lives in the
  Open-Game-Standards knowledge base (knowledge/README.md bridge).
